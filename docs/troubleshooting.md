# hfp - all in one 排查指南

先保护当前内容，再沿实际失败阶段检查。保存失败时用画布里的“下载当前内容”留存备份；生成结果是否已提交尚不明确时，先查询原任务。不要删除数据库、重置配置或连续点击生成来排查。

## 按现象定位

| 现象 | 先检查什么 | 对应处理 |
| --- | --- | --- |
| 页面无法打开 | `43123` 是否监听，前端日志是否报错或换了端口 | 按[本地开发](local-development.md)启动，使用固定地址与 `--strictPort` |
| 首页能开，接口报错 | `43180`、Vite 转发目标、`/api/health/ready` | 检查 Go 启动日志、数据目录和数据库状态；首页能开不等于后端正常 |
| “画布尚未保存，未开始生成” | 保存提示、操作请求的状态与原因 | 先修保存，再生成；这是生成前的保护 |
| 保存返回“缺少可信身份” | 是否使用正确的本机 URL、后端是否先启动、`BEEFTV_DEV_OWNER_TOKEN_FILE` 是否指向当前数据目录 | 按启动说明建立同源开发身份；只设置 `BEEFTV_UI_BOOTSTRAP` 不够；不要关掉后端校验 |
| 保存版本冲突 | 画布是否在多个入口修改，后端版本是否更新 | 保留本地草稿，使用产品的版本/合并流程；不要直接覆盖新版本 |
| “接口类型 … 未安装” | `plugin-packages/` 是否有打包后的文件，`/api/plugins` 是否启用对应接口 | 运行 `build-packages.sh` 并重启后端；插件源码目录不能直接用于请求 |
| “助手没有启动成功” | `agent-host/node_modules`、`agent_config.json` 的启动命令与文件位置、Node 版本 | 按首次准备安装和配置；再检查 `/api/assistant/status`，必要时读取后端日志 |
| 助手能打开但不回复 | 对话记录中的失败原因、模型渠道是否可达、当前模型接口类型 | 把本地启动成功与外部模型成功分开验证；公司内网渠道需要相应网络连接 |
| “没能读取对话” | 助手状态、UI 会话是否仍有效、`/api/assistant/history` 的错误 | 先恢复助手；后端重启后重新取得会话；保留已有 `sessions/` |
| “模型不接受当前参数”或“请求尚未提交” | 任务详情和 `failureDiagnostics.requests` | 查实际 HTTP 状态及响应摘要，不能直接归因为提示词或网络 |
| 模型返回 `404 Invalid URL` | 渠道基础地址、模型接口类型、实际发送路径 | 中转站的 OpenAI 兼容接口与厂商原生接口可能不同；确认该渠道支持的路径后修改，不能仅按模型品牌推断 |
| 生成成功但画布没更新 | 任务结果状态、资源下载、绑定回执、节点是否仍存在 | 优先取回原结果；下载/绑定失败不应重新发起付费生成 |
| Bun 报 `Unknown lockfile version` | Bun 版本及出错的锁文件 | 助手清单需要 Bun 1.4.4 或更新版本；保持 `--frozen-lockfile`，不要删锁文件重解依赖 |
| Go 报缓存目录必须为绝对路径 | `GOCACHE` / `GOMODCACHE` | 使用仓库根目录的绝对路径；见启动说明 |

## 团队服务器

| 现象 | 先检查什么 | 对应处理 |
| --- | --- | --- |
| 登录或任何写操作返回 403 `origin_forbidden` / `origin_required` | 反向代理是否保留了 `Host`，`X-Forwarded-Host` 是否来自 `TEAMSERVER_TRUSTED_PROXIES` 里的地址 | Caddy 默认保留 `Host`；nginx 需 `proxy_set_header Host $host`；Compose 外的代理把它的地址加进 `TEAMSERVER_TRUSTED_PROXIES`。不要关掉来源校验 |
| 用 `http://` 访问时，登录后马上又回到登录页 | `.env` 里是否写了 `TEAMSERVER_COOKIE_SECURE=true` | 删掉这一行（默认 `auto` 会按访问方式处理）；Compose 外自建代理时要转发 `X-Forwarded-Proto` |
| 构建停在 `go: downloading` 很久，最后报 `proxy.golang.org … unexpected EOF` | 构建输出里 `backend-build` 步骤下载的地址；`.env` 里的 `GOPROXY` | 拉取最新代码后重新 `docker compose up -d --build`：默认先走国内镜像，下载和编译共用模块缓存，断续时自动重试且保留已下完的模块。`.env` 里写过 `GOPROXY=https://proxy.golang.org…` 的删掉或改成公司可用的镜像 |
| 端口冲突，或改了端口仍占用 80 | `.env` 里的 `TEAMSERVER_HTTP_PORT` | 对外端口只认 `TEAMSERVER_HTTP_PORT`（例如 `180`），改完 `docker compose up -d`；不要用 `TEAMSERVER_ADDR` 或 `TEAMSERVER_DOMAIN=:180` 改端口。默认部署不再占用 443 |
| 成员的“模型配置”里没有公司中转站 | 启动日志开头的“公司模型服务”一行，或管理员“管理 → 服务状态” | 显示“未配置”说明 `TEAMSERVER_RELAY_CHANNEL_FILE` 没设或没写进 `deploy/teamserver/.env`；路径要写容器内的 `/config/relay-channel.json`。管理员在自己“模型配置”里添加的服务不会分发给其他人 |
| 改了 `relay-channel.json` 并重启后，成员看到的公司中转站模型没变 | 侧栏“管理 → 服务状态”里公司模型服务的来源 | 来源是“网页编辑”时，网页保存的定义优先于文件：在“模型配置”里直接编辑公司中转站，或在“服务状态”确认后恢复为配置文件 |
| 管理员在“模型配置”里加的模型，其他成员看不到 | 加在了哪张卡片上 | “添加模型服务”和“我的模型服务”只属于你自己的工作区。要让所有成员用自己的密钥调用，点公司中转站卡片的“编辑（所有成员）”添加 |
| 改了账号文件没生效 | `docker compose logs teamserver` 里的“账号文件有误”行 | 按提示的行号改正（常见：缺冒号、密码不足 8 位、用户名重复、密钥文件里的用户不在账号文件中）；整份改对之前沿用原有账号 |
| 启动即退出，提示读取账号文件失败 | 文件路径和权限 | 路径是容器内的 `/config/...`；文件需对 UID 10001 可读（`chown 10001` 后 `chmod 600`） |
| “用户管理”里重置密码提示由账号文件管理 | 该账号带“账号文件”标记 | 改服务器上的账号文件；显示名称和角色仍可在网页修改 |
| 进程启动即退出，提示环境变量 | 日志里列出的变量（如 `CANVAS_ALLOW_PRIVATE_UPSTREAMS`、`BEEFTV_AGENT_HOST_TOKEN`） | 团队服务器拒绝会让各工作区共用凭据或打开私网出站的设置；删掉这些变量，内网中转站用 `CANVAS_ALLOWED_PRIVATE_UPSTREAM_HOSTS` 精确放行 |
| 页面提示“工作区暂时无法打开”（503 `workspace_unavailable`） | `docker compose logs teamserver` 里的 `open workspace=…` 行 | 常见原因是官方插件目录缺失、数据卷权限或磁盘已满；修好后刷新即可重试 |
| “公司中转站”渠道显示“等待管理员绑定” | 用户管理里该成员的中转站密钥 | 管理员绑定后无需重启，下次打开模型配置即生效 |
| 读取模型或生成提示“不允许访问本机、内网或链路本地地址” | 目标地址是否在“服务状态”的内网放行名单里 | 公司中转站渠道的地址会自动放行；成员自己添加的其他内网服务要把主机名或 IP（如 `10.10.10.45`，不写端口）写进 `CANVAS_ALLOWED_PRIVATE_UPSTREAM_HOSTS`，不要打开整个私网出站 |
| Seedance 视频一直“生成中”或提示 `404 Invalid URL` | `relay-channel.json` 里该模型的 `protocol` 和 `baseUrl` | 写 `"protocol": "volcengine-ark-video"`，`baseUrl` 写中转站的豆包入口（如 `http://10.10.10.45:3000/doubao/api/v3`）；改完重启团队服务器 |
| 生成提示“参考图没能通过公司参考图服务上传”或“公司参考图服务不接受你的中转站密钥” | 错误里的排查编号；公司参考图服务（8787）的日志和 `/health` | 用排查编号在 8787 日志里找到这次调用；服务的对象存储与德云配置需在服务端 `.env` 补齐；“不接受密钥”说明成员的中转站密钥无效或被停用；“结果未知”时服务会冻结该图片，需到德云后台核对后再试。模型尚未调用，修好后直接重试 |
| 生成视频弹出“需要在线素材链接” | `relay-channel.json` 里是否有模型配置了 `referenceAssetService`；该成员是否已绑定中转站密钥 | 配好参考图服务后，图片会自动换成临时链接，不再弹窗；参考视频、参考音频仍需在线链接或另配对象存储 |
| 中转站显示视频已完成，但画布一直“上游生成中”或最后失败 | “管理 → 错误记录”或任务详情里的任务日志：“上游任务状态：…”各行和失败消息里的“上游状态 …” | 日志会写出中转站每次返回的状态词；“没有任务状态”“未识别的状态”“找不到视频地址”会列出返回的字段名，按这些字段核对中转站版本和协议。失败消息带的原因来自中转站自己的任务记录（如 `fail_reason`），属于中转站侧问题时到中转站后台按上游任务号查。也可在服务器上用成员密钥直接查询：`curl -s -H "Authorization: Bearer <成员密钥>" http://10.10.10.45:3000/doubao/api/v3/contents/generations/tasks/<上游任务号>`（转发前删掉返回里视频地址的签名部分） |
| 中转站后台显示视频已完成，但任务日志一直是“queued，进度 0%”，十几分钟后失败并提示“上游判定失败但没有给出原因” | 中转站（New API）自己的任务日志里按上游任务号（`task_…`）搜索，以及中转站容器日志里含该任务号的 `poll` 告警行 | 中转站只是把任务转给它的上游，再定时去上游查进度。它一次都没查到时，交给本系统的进度一直是 0%；连续查询失败约 20 次（`TASK_POLL_MAX_FAILURES`，约 12 分钟）后自行判失败，原因是 “Failed to query the upstream task status”。这时视频往往已经在上游生成（后台显示成功、任务号是 `cgt-…` 的那条通常是上游的记录），问题在中转站到上游这一段：核对该模型所用渠道的地址、上游类型和密钥，按告警行里的 HTTP 状态和返回内容修正。本系统无法绕过中转站取回这条视频；中转站修好后新任务即可正常取回。任务详情里的“取回结果”会显示中转站当前给出的状态和原因 |
| 生成失败提示“提交结果尚未确认：模型服务暂时不可用” | 错误记录里的 HTTP 状态 | 创建请求收到 5xx 时无法确定中转站是否已接单，系统不会自动重发；到中转站后台核对是否已生成，确认没有再重新提交 |
| 自己添加的模型服务，刷新后密钥变空 | 是否用的是自己的中转站密钥 | 旧版本把与公司中转站相同的密钥也清空了，已修复；升级前刷新后又改过设置的，需要重新填一次密钥 |
| 内网用 `http://IP` 打开时，重试生成、作品入库或工坊复制报错 `crypto` / `digest` | 浏览器地址是否为非本机的 HTTP | 已改为不依赖浏览器的安全上下文；升级后刷新页面即可 |
| 公司中转站提示“管理员还没有为你绑定公司模型服务的密钥” | 用户管理里该成员的“中转密钥”列 | 在 `user-keys.txt` 加一行或在“用户管理”绑定；密钥只保存在服务器，浏览器里看不到 |
| 任务进度、助手回复卡住或中途断开 | 反向代理是否缓冲了流式响应 | Caddy 示例已设 `flush_interval -1`；nginx 需对 `/api/` 关闭缓冲并把读超时设到 1 小时 |
| 技能页提示“未配置技能市场” | 是否在团队服务器上访问 | 桌面版和单工作区开发服务没有默认市场；团队服务器会自动接入站内市场 |
| 投稿到创意工坊被预检拦下 | 预检列出的问题和节点 | “只保存在浏览器里”的素材需重新上传；“文件不存在”需恢复或删掉对应节点；画板未保存需打开画板保存一次 |
| 技能投稿提示 SKILL.md 缺少元信息 | SKILL.md 开头是否有写错的头信息 | 没有头信息时会自动补；已有但不合规（如名字含空格或大写）需改成小写字母、数字和连字符 |

## 从哪里取证

- **页面**：画布保存状态、任务“查看详情”、助手对话及错误；复制排查信息前确认其内容适合分享。
- **本地服务**：`.local/logs/backend.log`、`.local/logs/web.log`。程序由其他终端启动时，输出可能仍在原终端。
- **团队服务器**：`docker compose logs teamserver`；管理员“用户管理 → 操作记录”可查账号、审核和下架操作。
- **任务**：`GET /api/tasks/:id` 返回阶段、结果状态及失败诊断。`dispatched`、HTTP 状态和 `requestId` 比笼统的页面标题更能定位失败边界。
- **助手**：`GET /api/assistant/status` 用于本地就绪检查；会话与模型请求诊断保存在工作区中。不能把内部日志原文直接发给模型或公开提交。
- **代码入口**：按[仓库地图](repository-map.md)找负责该阶段的模块；不要同时改页面、传输和服务端来掩盖一个未定位的问题。

## 验收与恢复

一次恢复至少确认“操作成功 → 后端读回 → 页面显示 → 刷新后仍在”。遇到异步模型请求，还要区分未发送、明确拒绝、结果不确定、已生成但未取回四种状态。未知结果先查询原任务；真实模型验证记录所用渠道/模型、任务结果和限制，不写密钥。

同类尝试连续三次失败时，停止重复操作，整理已排除的条件，换验证方式。需要用户介入时说明具体障碍，例如当前网络无法访问公司中转站，而不是泛称“环境问题”。

原生桌面的正式安装位置是 `/Applications/hfp-allinone.app`，更新使用 `scripts/update-local-beeftv-app.sh`。默认数据目录使用系统配置目录下的 `hfp-allinone`；新目录不存在且旧 `BeefTV` 目录存在时沿用旧目录，不搬迁数据。浏览器开发继续使用 `.local/project-workbench-debug`。
