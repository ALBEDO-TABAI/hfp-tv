# 团队服务器

团队服务器（`backend/cmd/teamserver`）用一个进程服务多名成员，每人一个独立工作区。它面向 10–30 人、账号由管理员分配的内部团队。架构取舍和后续分期见 [团队服务器与创意工坊方案](../../../team-server-and-workshop.md)。

当前实现了方案的第一期“多人底座”（账号、会话、网关、内核池、公司中转站渠道和部署镜像）、第二期“创意工坊”（项目投稿、审核、只读浏览与复制）和第三期“技能市场”（投稿、审核、签名与安装都在团队服务器内完成，不依赖上游服务）。配额与总并发等第四期加固尚未实现。

## 运行结构

```text
浏览器 ──HTTPS──> Caddy ──> teamserver（一个进程）
                              ├─ /api/platform/*   账号、会话、用户管理（platform.db）
                              ├─ 其余 /api/*        会话 → 用户 → 工作区内核 → 内核路由
                              └─ 其他路径           前端静态文件（TEAMSERVER_WEB_DIR）
内核 = bootstrap.ProfileHosted 运行时；每人一份数据目录、一个 SQLite、一个按需启动的 Node 助手子进程
```

数据目录（`TEAMSERVER_DATA_DIR`，镜像内为 `/data`）：

| 路径 | 内容 |
| --- | --- |
| `platform.db` | 账号、会话、邀请、工作区登记、管理员操作记录 |
| `secrets/` | 平台加密密钥（加密中转站密钥）和技能签名私钥 `skillhub-signing.key`，权限 0700 |
| `market/archives/` | 技能市场的投稿与发布包，按 SHA-256 命名，只写一次 |
| `community/blobs/sha256/` | 创意工坊的作品快照和媒体文件，按 SHA-256 命名，只写一次 |
| `workspaces/<工作区ID>/` | 与桌面版相同的单机数据目录：SQLite、资源、模型配置、助手数据 |

服务启动时会打开所有启用中的工作区，让重启前排队或进行中的生成任务继续执行。停用账号会立即作废会话并关闭该工作区内核。

## 信任边界

- 目标工作区只由服务端会话决定。请求里的路径、请求头和 ID 都不能改变它。
- 网关认证后，在进程内 context 里标记“本工作区所有者”（`httptransport.WithHostedOwner`）。内核原有的本机同源判断、owner 校验、助手界面会话签发都认这个标记。浏览器无法用请求头伪造它。
- 网关转发前删除 `X-Desktop-Token` 和全部 `X-Beeftv-*` 请求头（保留 `X-Beeftv-Ui-Session`），并删除 Cookie。
- 每个内核另开一个 `127.0.0.1` 随机端口，只供自己的助手子进程回调，要求该内核独有的启动令牌。助手回调地址由内核钉住，不从浏览器请求推导。
- 托管内核不提供下列接口，内核和网关两层都会拒绝，返回 404 `hosted_unavailable`：`PUT /assistant/host/config`、`/agent-clients*`、`/ops/clients`、`/plugins/eagle/*`、`POST /plugins`、`DELETE /plugins/:id`、`POST /depth-captures`、`/diagnostics/*`、`POST /beefapi/connection/start|cancel`。
- 助手子进程的启动命令由部署配置固定（`TEAMSERVER_AGENT_HOST_COMMAND`/`ARGS`），只继承白名单环境变量（PATH、HOME、语言、时区、临时目录、证书、代理）。
- 写请求必须带本站 `Origin`（或 `Sec-Fetch-Site: same-origin`）；会话 Cookie 为 `HttpOnly`、`SameSite=Lax`，HTTPS 访问时加 `Secure`（默认按 TLS 或可信代理的 `X-Forwarded-Proto` 自动判断）。
- 后台任务和事件循环的 panic 会被捕获并记录。一个工作区的任务出错不会让整个进程退出。

### 进程级环境变量

`internal/outbound` 在每次连接时读取私网出站开关，所以它对所有工作区生效。团队服务器启动时：

- `CANVAS_ALLOW_PRIVATE_UPSTREAMS` 未设置时自动设为 `false`；显式设为其他值会拒绝启动。公司中转站渠道 `baseUrl` 的主机自动加入放行名单（渠道文件由运维写，不由成员写）；其他内网主机用 `CANVAS_ALLOWED_PRIVATE_UPSTREAM_HOSTS` 按主机名或 IP 精确放行。链路本地地址（含云元数据）始终拒绝。
- 下列变量会让所有工作区共用同一凭据或信任，设置了就拒绝启动：`BEEFTV_AGENT_HOST_TOKEN`、`BEEFTV_OWNER_TOKEN`、`BEEFTV_UI_BOOTSTRAP`、`BEEFTV_ALLOWED_ORIGINS`、`BEEFTV_AGENT_BASE_URL`、`BEEFTV_AGENT_API_KEY`、`BEEFTV_AGENT_MODEL`、`BEEFTV_AGENT_PROTOCOL`、`BEEFTV_AGENT_HOST_URL`。

## 部署

部署文件在 `deploy/teamserver/`。镜像包含 Go 网关与内核、Node 24 助手宿主及依赖、ffmpeg、官方插件包和前端构建产物。

```bash
cd deploy/teamserver
cp .env.example .env   # 默认内网 HTTP；有域名时按注释启用 docker-compose.https.yml
docker compose up -d --build
# 创建首个管理员（密码从标准输入读一行，不进 shell 历史）
read -rs PW; printf '%s\n' "$PW" | docker compose exec -T teamserver teamserver admin create --username admin --display-name 管理员
```

`docker-compose.yml` 默认只让 Caddy 在 `TEAMSERVER_HTTP_PORT`（默认 80）上提供 HTTP；叠加 `docker-compose.https.yml`（在 `.env` 写 `COMPOSE_FILE=docker-compose.yml:docker-compose.https.yml` 和 `TEAMSERVER_DOMAIN`）后改为域名自动 HTTPS 并开放 443。`.env` 通过 `env_file` 整体传进团队服务器容器；容器内监听地址 `TEAMSERVER_ADDR=:8080` 和数据目录在 Compose 里固定。启动日志开头会打印实际读到的公司模型服务、内网放行名单、Cookie 模式和空闲回收设置。

构建时 Go 依赖默认从 `https://goproxy.cn|https://proxy.golang.org,direct` 下载（国内镜像出任何错都换官方源），下载和编译共用 BuildKit 的模块缓存：只有第一次构建或依赖版本变化时联网，下载断续时自动重试，已下完的模块保留到下次构建。公司有自己的 Go 代理时在 `.env` 设置 `GOPROXY`。

成员账号可以用两种方式管理，可以混用：在服务器上维护账号文件（见下节），或者管理员登录后在侧栏“管理”分组进入“用户管理”，创建账号、发邀请链接、绑定中转站密钥。忘记管理员密码时运行 `teamserver admin reset-password --username admin`（同样从标准输入读密码），这会使该账号的所有会话失效。

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `TEAMSERVER_DATA_DIR` | `/data` | 数据根目录 |
| `TEAMSERVER_ADDR` | `:8080` | 监听地址；只由反向代理访问，不要直接暴露到公网。Compose 中固定，对外端口用 `TEAMSERVER_HTTP_PORT` |
| `TEAMSERVER_HTTP_PORT` / `TEAMSERVER_HTTPS_PORT` | `80` / `443` | 仅 Compose：Caddy 对外端口；HTTPS 端口只在叠加 `docker-compose.https.yml` 时开放 |
| `TEAMSERVER_WEB_DIR` | 镜像内 `/app/web` | 前端构建产物；为空时只提供 API |
| `TEAMSERVER_COOKIE_SECURE` | `auto` | `auto`：直接 TLS 或可信代理的 `X-Forwarded-Proto: https` 时加 `Secure`；`true` 始终加（只走 HTTPS）；`false` 始终不加 |
| `TEAMSERVER_IDLE_TIMEOUT` | `30m` | 工作区内核最后一次请求后空闲多久关闭（至少 `1m`）；没有排队或运行中的任务、助手不在回复时才关闭，下次请求自动打开。`off` 表示不回收 |
| `TEAMSERVER_USERS_FILE` | 空 | 账号文件，每行 `用户名:密码`，见下节 |
| `TEAMSERVER_USER_KEYS_FILE` | 空 | 密钥文件，每行 `用户名:中转站密钥`；只能和账号文件一起用 |
| `TEAMSERVER_TRUSTED_PROXIES` | `127.0.0.1,::1`（Compose 中为 `172.16.0.0/12`） | 允许其 `X-Forwarded-For` / `X-Forwarded-Host` / `X-Forwarded-Proto` 生效的反向代理 |
| `TEAMSERVER_ALLOWED_ORIGINS` | 空 | 除本站外允许发写请求的来源，逗号分隔 |
| `TEAMSERVER_AGENT_HOST_COMMAND` / `TEAMSERVER_AGENT_HOST_ARGS` | 镜像内为 `node` 与 `["/app/agent-host/server.mjs"]` | 助手子进程命令；`ARGS` 是 JSON 字符串数组 |
| `TEAMSERVER_RELAY_CHANNEL_FILE` | 空 | 公司中转站渠道定义文件，见下节 |
| `TEAMSERVER_REFERENCE_STORAGE_FILE` | 空 | 参考素材对象存储配置（`referencestorage.Config` 的 JSON），写入每个工作区 |
| `TEAMSERVER_MARKET_ADDR` | `127.0.0.1:18090` | 内置技能市场的内部监听地址，只能是本机回环；要保持固定，内核保存的投稿授权和这个地址绑定 |
| `TEAMSERVER_WORKSHOP_MAX_MB` | `2048` | 单次创意工坊投稿的文件总大小上限 |
| `CANVAS_SHUTDOWN_TIMEOUT` | `2m` | 每个内核关闭时等待后台任务的上限 |

团队模式下前端用 `fetch` 读取画布事件流（`web/src/services/api/canvas-events.ts`），能拿到 401 并在 HTTPS 下工作。画布里的图片和视频直接使用 `/api/resources/<id>/file`（由会话 Cookie 认证），浏览器只加载屏幕上可见的媒体，视频按 Range 流式播放；桌面版因为资源接口需要启动令牌头，仍先下载到浏览器缓存。画布改动经事件流推送，事件流每 250 毫秒只查画布的 revision 列，不再整份读取；团队模式下兜底的整画布轮询为 60 秒一次（桌面版 4 秒）。团队模式下上传的图片、视频与素材库、画板等都写入工作区的服务器资源（与桌面版相同的后端路径），不使用浏览器本地存储；修复前上传、只留在浏览器里的素材需要重新上传。Caddy 示例配置对流式响应设置了 `flush_interval -1`。改用 nginx 时，`/api/` 需要关闭缓冲（`proxy_buffering off`），并把读超时设到 1 小时，否则任务事件流和助手对话会被截断。

### 账号文件

设置 `TEAMSERVER_USERS_FILE` 后，团队服务器在启动时和之后每 5 秒检查账号文件，把文件内容同步进平台库。登录仍走登录页和会话 Cookie，每人仍是独立工作区；文件只是另一种开账号的方式，适合由运维直接在服务器上维护名单。

- **格式**：账号文件每行 `用户名:密码`，密钥文件（`TEAMSERVER_USER_KEYS_FILE`）每行 `用户名:中转站密钥`。按第一个冒号分隔，所以密码和密钥本身可以含冒号；`#` 开头的行和空行忽略。用户名规则与网页创建相同，密码至少 8 位。密码可以写明文，也可以写 `teamserver hash-password` 生成的 argon2id 哈希（从标准输入读一行密码，输出整行哈希）。示例见 `deploy/teamserver/config/users.example.txt` 与 `user-keys.example.txt`。
- **生效方式**：加一行即创建账号（成员角色）和工作区；改密码后此人所有会话失效、需重新登录；改密钥立即写入此人的工作区；删掉一行即停用账号并关闭其工作区内核，数据保留，再加回来恢复原工作区。内容要连续两次读取一致才同步，编辑器写到一半的文件不会被应用。
- **出错时**：任何一行有问题，整份文件都不生效，现有账号保持原样，日志指出文件和行号，不会打印密码或密钥。启动时文件有误则进程直接退出。账号文件里一个账号也没有也算错误，防止误清空把所有人停用。
- **与用户管理的分工**：文件里的账号在“用户管理”中带“账号文件”标记，密码、密钥和启用状态只能改文件；显示名称和角色仍可在网页修改。成员本人也不能在账号菜单里改密码。网页创建的账号（包括 `admin create` 创建的管理员）不受文件影响；如果文件写了一个已有的用户名，该账号转为由文件管理。
- **文件权限**：文件里可能有明文密码和密钥。容器内以 UID 10001 运行，建议 `chown 10001 users.txt user-keys.txt && chmod 600 users.txt user-keys.txt`；文件对其他用户可读时日志会提醒。

### 公司中转站渠道

`TEAMSERVER_RELAY_CHANNEL_FILE` 指向一个模型渠道 JSON 对象，格式与模型配置里的渠道相同，但不能包含 `apiKey`、`secretKey` 或 `credentialRef`。示例见 `deploy/teamserver/config/relay-channel.example.json`；Compose 把 `deploy/teamserver/config` 挂载到容器的 `/config`，因此可设为 `/config/relay-channel.json`。

服务端会把它写进每个工作区的模型配置，渠道 ID 固定为 `company-relay`，密钥用管理员为该成员绑定的中转站密钥。所有成员的请求都发往同一个 `baseUrl`，各自带自己的密钥。管理员在自己的“模型配置”里添加的服务只属于自己的工作区，不会分发给其他成员。规则如下：

- 未绑定密钥时渠道处于停用状态；绑定、换绑或清除后立即改写配置。助手子进程在下次状态检查时用新密钥重启。
- 成员保存模型配置时，这个渠道总会恢复成平台写入的样子，成员不能修改或删除它，也不能伪造同 ID 的渠道。
- 中转站密钥在平台库里加密保存，管理界面只显示末四位。
- `modelProfiles[].baseUrl` 可以给单个模型指定中转站上的其他入口（例如 Seedance 走 `/doubao/api/v3`，其余走 `/v1`），但必须与渠道 `baseUrl` 同协议、同主机和端口，加载渠道文件时校验。服务端为该模型补密钥时改用这个地址；模型目录仍读渠道 `baseUrl`。Seedance 用 `protocol: "volcengine-ark-video"`。
- `modelProfiles[].referenceAssetService` 指向公司参考图服务（`POST` 图片原始字节，`Authorization: Bearer <成员中转站密钥>`、`X-HFP-Reference-Mode: seedance-asset`，返回 `{"url":"asset://…"}`）。只有平台渠道的模型会带上它，成员任务里自带的同名字段在创建任务时被丢弃。视频任务执行前，`app/platform_reference_assets.go` 把素材库里的参考图逐张登记并改写为 `asset://`，成功的编号按资源缓存在 `ark_private_asset_bindings`（`project_name` 为 `reference-service:<地址>`）；不是素材库资源的参考图会被拒绝。`POST /api/resources/:id/ark-private-asset`（预先登记）在团队服务器上也走这条路径。服务地址启动时校验并自动加入内网放行名单。成员自己添加的渠道若协议为 `volcengine-ark-video` 且地址与公司中转站同协议同主机端口，创建任务时也补上公司的参考图服务（用该渠道自己的密钥鉴权），其他地址一律不带。
- 参考图服务调用失败（不可达、超时、非 200、返回值不可用）是 `generation.ReferenceRelayError`，归类为 `reference_relay_failed`，401 为 `reference_relay_unauthorized`；两者都表示模型尚未调用，不自动重发、允许手动重试，错误里的排查编号就是发给服务的 `X-HFP-Request-ID`。
- **密钥只在服务端**：`GET /api/workspace/model-config` 返回的平台渠道 `apiKey`、`secretKey` 为空，另带 `hasApiKey` 表示是否已绑定。服务端在三处补上密钥，并始终改用渠道保存的 `baseUrl`，密钥只会发往管理员配置的地址：创建任务时 `config.channelId` 为 `company-relay`；`POST /api/ai/models` 带 `channelId: "company-relay"`；`/api/ai/custom` 中转请求没带密钥、且目标与该渠道同协议同主机端口。成员自己添加的渠道仍由浏览器携带本人填写的密钥；即使成员填的正好是自己的中转站密钥，也原样返回给本人，只清空配置顶层等旧版本留下的副本。实现见 `internal/app/platform_credential.go` 与 `internal/handler/workspace.go` 的 `redactPlatformChannels`。

### 参考素材

托管内核不注册匿名资源下载路由。需要公网地址的模型协议按以下顺序取得链接，其余协议沿用内嵌素材：

1. `TEAMSERVER_REFERENCE_STORAGE_FILE` 配置的 S3 兼容对象存储（图片、视频、音频）。
2. 没有配置对象存储、而公司渠道有 `referenceAssetService` 且成员已绑定密钥时，图片经该服务的 `public-url` 模式换成临时 HTTPS 链接（`X-HFP-Reference-Mode: public-url`，返回 `{"url":"https://…","expiresAt":"…"}`），按资源在内存里缓存到失效前 30 分钟。参考视频和音频不走这条路，仍提示成员提供在线链接。

`generation.ReferenceStoragePort.Enabled(kind)` 按素材类型回答能否中转，接单前的素材检查只放行能中转的类型。实现见 `internal/app/generation_reference_storage.go`。

## 创意工坊

成员把自己的项目投稿到创意工坊，管理员审核后，所有登录成员都能只读浏览，并一键复制到自己的工作区（`backend/internal/workshop`，内核侧快照在 `backend/internal/projectsnapshot`）。

- **项目与快照**：一个项目是共用同一个 `workspaceProjectId` 的若干张画布。投稿时内核把整组画布、画板和全部引用的媒体导出成一份不可变快照：媒体按 SHA-256 存进 `community/blobs`，文档里的 `resource:<id>` 和资源地址改写成 `workshop:<sha256>` / `workshop://<sha256>`；素材记录 ID、任务 ID、助手对话、视口和项目归属都不进快照。
- **预检**：只存在浏览器里的素材、缺失或未上传完成的文件、未保存的画板、超出大小上限会阻止投稿；外部链接、仍在生成的节点、疑似密钥或手机号只作提醒。
- **审核**：同一项目的新投稿会替代还在待审的旧稿。管理员审核时看到的是只读画布、文件清单和与上一版的差异，通过时必须带上看到的快照摘要，作者在此期间更新或撤回会让审批失败。审核前除作者和管理员外没有人能读到快照和文件。
- **浏览与文件**：文件只能经由“当前可见的版本”读取。图片、视频和音频在站内预览，其他类型（含 SVG、HTML）一律按附件下载并带 `sandbox` 安全头。作者可选择是否允许下载原文件；不允许时界面不提供下载按钮，但浏览器里能预览的内容在技术上仍可另存。
- **复制**：复制在服务端完成：为每个文件在目标工作区建立资源（同一文件再次复制会复用），重建素材记录并改写节点的 `assetId`，用新 ID 写入画布和画板，失败时删除已建的画布和素材记录。同一个请求 ID 重复提交返回同一份副本。原作品更新、下架都不影响已有副本。
- **改编**：从工坊复制来的项目再投稿时，会自动标注“改编自……”，作者不能去掉；来源下架后显示为“改编自（已下架作品）”。

## 技能市场

技能市场和团队服务器一起部署，投稿、审核、公共技能的存储都在企业服务器内（`backend/internal/skillmarket`）。

- **接口**：市场实现工作区内核已有客户端使用的 SkillHub v1 合同（`internal/skillhub`），挂在只监听本机回环的内部端口 `TEAMSERVER_MARKET_ADDR` 的 `/skillhub/v1` 下，公网入口访问不到。启动时团队服务器把 `BEEFTV_SKILLHUB_URL`、`BEEFTV_SKILLHUB_TRUSTED_KEYS` 和 `BEEFTV_SKILLHUB_REQUIRE_SIGNATURE=true` 设给所有内核，外部设置的同名变量会被忽略。
- **授权**：成员在“技能 → 我的投稿”点“连接投稿账号”，应用打开站内的 `/skills/authorize?code=…`，确认后回到投稿页点“检查授权状态”。授权有效期 30 天；停用账号后授权立即失效。
- **投稿**：沿用现有投稿流程（准备 → 上传私有草稿 → 检查公开预览 → 确认送审）。市场按安装端的严格规则校验技能包：只接受文档、数据和图片文件，不接受 `scripts/`，`SKILL.md` 必须有 `name`/`description` 头信息。在应用里写的技能如果没有头信息，准备投稿时会按技能名和简介自动补上。
- **审核**：管理员在“技能审核”页查看待审稿件、逐个文件阅读正文（纯文本显示，不渲染 HTML）、对比上一版的增删改，然后通过、通过并设为官方，或填写原因驳回。审核绑定管理员看到的版本，作者在此期间改动会提示刷新。
- **发布与安装**：通过后平台用 `secrets/skillhub-signing.key` 的 Ed25519 私钥签名，内核只安装签过名且内容与签名一致的版本。下架只影响搜索和新安装，已装到工作区的副本不受影响。
- **没有团队服务器的安装**（桌面版、单工作区开发服务）默认不连接任何市场，技能页提示“未配置技能市场”；需要时用 `BEEFTV_SKILLHUB_URL` 指定。

| 管理与授权接口 | 说明 |
| --- | --- |
| `GET /api/platform/market/authorizations/:userCode`、`POST …/approve` | 站内确认页读取与批准设备授权（需登录） |
| `GET /api/platform/admin/skill-submissions?status=pending\|processed` | 待审核或已处理的稿件 |
| `GET /api/platform/admin/skill-submissions/:id`、`…/file?path=` | 稿件详情、上一版文件清单、单个文件内容 |
| `POST /api/platform/admin/skill-submissions/:id/approve` | `{revision, previewDigest, official}`；稿件已变化时 409 `submission_changed` |
| `POST /api/platform/admin/skill-submissions/:id/reject` | `{revision, reason}`；原因必填 |
| `GET /api/platform/admin/market-skills`、`POST …/:skillId/unlist\|relist` | 已发布技能列表、下架与恢复 |

信封与本地 API 相同：成功 `{ code: 0, data, msg }`；失败时 HTTP 状态与 `code` 一致，并带机器可读的 `reason`。未登录访问任何工作区接口都返回 401 `unauthenticated`。

| `POST /api/platform/login` | `{username, password}`；失败统一为 `invalid_credentials`，同一用户名+IP 15 分钟内失败 8 次后返回 429 `too_many_attempts` |

## 错误记录

管理员在侧栏“管理 → 错误记录”查看成员的失败任务，不必再让成员截图。

- **收集**：工作区内核在任务写入失败终态后调用 `bootstrap.HostedConfig.ReportFailure`（`app/failure_report.go`，后台执行，不阻塞任务处理），`kernelpool` 给每个内核的回调带上工作区 ID，由 `internal/errorlog` 写入 `platform.db` 的 `error_events`。平台不读工作区数据库。网关打不开某个工作区内核时也记一条（同一错误一分钟一次）。
- **内容**：任务 ID、类型、模型、阶段、错误类别、成员看到的消息、上游任务号、HTTP 状态、上游详情和最近 12 行任务日志；保留最新 5000 条。
- **任务日志里的上游过程**：视频任务接单后记“上游已接单，任务号 …”；每次查询结果的状态或进度变化都记“上游任务状态：…，进度 …%”；查询结果没有状态字段、状态词无法识别、已完成却找不到视频地址时，记下返回的字段名（`generation/poll_observer.go`）。除上游任务号外只记状态词和字段名，不记结果地址或密钥。
- **公司中转站的返回格式**：New API 中转站会用自己的任务格式回应，除插件声明的字段外，完成时还会从 `metadata.url`、`result_url`、`data.result_url`、`data.fail_reason`（成功时存放视频地址的旧写法）和 `data.data.content.video_url` 读取视频地址；失败时的原因从 `data.fail_reason`、`error.message` 等字段读取，并附上原始状态词，例如“上游视频取回超时（上游状态 FAILURE）”。

## 备份

备份时停止服务，或对 `platform.db` 和每个 `workspaces/*/open_ai_canvas.db` 用 SQLite 在线备份，再增量复制 `secrets/`、`market/`、`community/` 与各工作区的资源目录。`secrets/` 丢失后已绑定的中转站密钥无法解密，需要重新绑定；技能签名私钥也会变化，已发布的技能需要重新审核发布才能被内核信任。

## 尚未完成的部分

- 没有存储配额和跨工作区的生成总并发上限：每个内核各自按默认并发 3 执行。
- 空闲回收以整个工作区内核为单位（含助手子进程），没有单独提前停掉助手；浏览器标签页保持打开并持续请求时，内核不会被回收。
- 每次整页加载都会把成员的全部画布读入浏览器（画布仓库按“全部在内存”设计），画布很多时首次加载较慢；生成任务进行中，进度和阶段变化仍会提交画布并让打开的页面重新读取整份画布（只有心跳时间变化时已不再提交）。需要改画布存储结构，暂未处理。
- 任务产物绑定的恢复循环每 5 秒把所有成功任务重放一遍（批量 64 个）；回放是幂等的，但工作量随历史任务增长。
- AI 超分只接上游 BeefTV 内置服务：团队模式隐藏了节点工具栏入口，“添加节点”菜单里仍有该节点，但会显示“暂无可用超分模型”。
- 镜像和 Compose 已在内网服务器试部署，尚未压测。
- 创意工坊复制是同步请求，大作品需要等待；文件直接复制进目标工作区，没有用硬链接省空间；被替代或驳回的版本文件不会自动清理。复制前不检查目标工作区是否配置了作品用到的模型。
- 技能市场没有上游的 MCP 查询端点和发布历史页（`GET /skills/:skillId`），现有客户端都不调用它们；审核结果只有站内状态，没有通知。
